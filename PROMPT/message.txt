### What the data analysis showed (this drives the design)

**Rows are facts.** Every row states 1–8 facts of the form (subject, attribute, value). The practice set has 514 distinct facts, and most are mentioned 2–49 times across the year.

**Each fact is a step function over time.** For example, Jules supports 8 languages and then 14 from Aug 2026. Most rows repeat the current value.

**Lies come in three kinds:**
- Invented values that are never true elsewhere (~42%).
- Stale values that were true earlier (~29%).
- Premature values that become true later (~17%).

**Whole pages lie.** Rows from one page (same date, consecutive ids) cluster: 11 pages are 100% false. Hedging ("I have been told") signals `unsure`. Speakers like `Gavin:` (the hype CEO) lie more often than average.

**Majority voting alone is not enough.** Naive "majority of other mentions" or step-function fitting without labels reaches only 80–85% on practice. The wins come from combining the timeline with page trust, labelled anchors and a learned meta-model.

**Scoring is not published.** The site only says confidence is part of the answer, so calibrated confidences matter.

## Recommended approach: a temporal truth-discovery engine (no LLM at runtime)

The engine is one Python package, `polygraph/`, used by both the Docker run and the frontend:

```
universe.csv + lexicon.json
   │
1. READER     deterministic value parser = a clone of the referee's value-forms.md
   │          (numbers, units, money, %, dates, versions, durations, names, yes/no, negation, ops)
2. LINKER     finds subjects via lexicon names/aliases (longest match);
   │          pronouns ("Its", "He") → the last subject named on the same page
3. ATTRIBUTOR picks the attribute for each value: a small classifier trained on the 2,400 practice facts
   │          (value kind + unit + cue words); cue lists for every attribute are written at build time by an LLM (allowed)
4. TRUTH ENGINE  per fact: a timeline of mentions → fit the step function (dynamic programming),
   │          iterating with PAGE TRUST (EM-style truth discovery); labelled rows are fixed anchors
5. JUDGE      per row: features (agreement with timeline, support, page trust, hedges, speaker, outlier…)
   │          → a gradient-boosted model trained AT RUNTIME on the labelled rows → calibrated P(true/false/unsure)
6. CLAIM FORGE builds a knowledge base of trusted facts → candidates of all 5 types → renders them with templates
   │          → validates each with our own referee clone (step 1 + claim-forms rules) → keeps the best 1,000, mixing types
7. WRITER     writes a safe fallback output within the first minute, then the improved one; atomic rename; watches ARENA_DEADLINE
```

Why this is efficient:
- **One parser does two jobs.** The value parser (step 1) reads the input rows and also checks our own claims. Every example in `contracts/*.md` is a free unit test.
- **We can train on what we're given.** Training at runtime on the 1,900 labelled rows means the model adapts to the real 20k distribution.
- **A safety net comes first.** A valid but dumb output (all `true` plus simple fact claims) ships in Phase 0, so we can never hand in nothing.

### Frontend concept (decided): Polygraph console, dark noir + neon

**Look:**
- Near-black background.
- Neon green for truth, red for hype, amber for unsure.
- Monospace readouts and subtle scanlines.

"Polygraph" is a lie-detector console for Hooly:
- **Live architecture diagram.** Built with React Flow. Each stage node lights up, and counters tick as rows flow through.
- **Run panel.** Paste or upload rows, or click "Load sample.csv". Each row gets a polygraph-needle animation, then a TRUE/FALSE/UNSURE stamp with its confidence.
- **Evidence board** (click a row). The fact's timeline appears as a step chart over the year. Every mention is a dot (green true, red false), the row is highlighted, and there's a one-line "why", e.g. "Stale: Jules went from 8 to 14 languages in Aug 2026".
- **Claim Forge tab.** The 1,000 claims, filterable by type. Each shows the facts it connects as a mini graph.
- **Hype meter.** Which pages and speakers lie most (a Gavin Belson joke writes itself).

### Data contracts fixed in Phase 0 (so everyone can work in parallel)

- **Trace JSON** (engine → UI), produced by `/run`:
  - `stages[]`: name, row count, ms.
  - `rows[]`: id, text, date, facts (subject, attribute, value, text span, status `agrees|stale|premature|invented|unknown`), page_trust, verdict, confidence, why.
  - `timelines{}`: per `subject|attribute`, the steps (from, to, value) and mentions (date, value, row_id, verdict).
- **KB interface** (truth → forge): `kb.timeline(subject, attribute) → [Step(start, end, value, confidence)]`, `kb.events → {name: date}`, `kb.links → (subject, link_attr) → target steps`.
- **Claims JSON**: id, type, text, form, confidence, `sources[]` (the facts it connects). Used by both the CSV writer and the UI.
